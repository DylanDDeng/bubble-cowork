# 应用层协作方案复审 04

日期：2026-10-05。结论：**采纳 03 的主要方向；修正四处边界后可作为实施依据，当前修订稿尚不宜标记完全通过**。

复审对象：[评审 03](agent-workflows-03.md) 及按其修订的 `docs/collaboration/README.md`，对照当前 runner 与已安装的 Claude Agent SDK 类型静态核查，未运行验证。本报告记录用户转交的复审意见，保留原样供追溯。

## 赞成采纳的 03 调整

- 先做通核心流程（Codex 实现 → Claude 审查，可加第三个并行 reviewer）；自然语言动态规划、自动重连、配置清理界面后置。
- 权限约束落在运行时；SDK 的 `tools` 配置可用，但与用户设置、插件、hook 的组合效果须实际验证。
- 审查固定版本：reviewer 读代码快照与 diff。
- 补齐修复与结束规则：复审知道上一轮问题，只有阻塞问题驱动修复，到轮数上限交用户。
- 原方案“证明所有可能写文件的进程都已停止”超出当前集成能力，03 的判断正确。

## 需要修正的四处边界

### 1. 审查副本不是沙箱

修订稿称“reviewer 即使越过只读策略写入，也只写进一次性副本”。切换工作目录、文件只读都不是沙箱；仍有越权执行能力时可以通过绝对路径触及原项目。应写成“副本固定审查输入；工具限制或沙箱负责限制写入”，不能承诺越权无害。

### 2. 版本关卡只能发现已经发生的变化

后台进程若在流程完成之后才写入，任何关卡都无法预知。成功应明确绑定“已验收的版本 R(n)”；修订稿已有该定义，但验收条款仍要求所有延迟写入都被发现，需要统一。

### 3. `interrupted` 不代表旧 Agent 已停止

可以不做自动重连，但在同一目录启动新的实现者之前必须确认旧执行已结束；无法确认就继续阻止派发。不能用重新拍快照代替停止确认。

### 4. 基础去重不能全部后置到 M1

专门的命令表可以后置，但用户双击开始、IPC 重试都不能启动两个实现者。M0 应保留启动请求 ID、唯一约束和状态检查。

## 产品选择（非技术必需）

- “自然语言计划必须再点一次开始”是产品选择。用户已说清“Codex 实现、Claude 审查”时可直接显示计划并执行；角色不明确、需要扩大范围或增加成员时再询问。
- “固定使用一到两周才推进下一阶段”建议改为按实际效果判断。

## 收敛后的用户流程

选择“实现 + 双审查” → Codex 实现 → 程序运行检查 → 两个 reviewer 审查同一份快照 → 有阻塞问题就修复并复审 → 必需检查和审查全部通过，标记该版本完成。应用负责启动、顺序、汇合与结束判断，Agent 负责实现与判断代码问题；UI 继续使用 Agent 胶囊/任务行，点击后右侧展开详情。
